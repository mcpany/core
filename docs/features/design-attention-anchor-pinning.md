# Design Doc: Attention-Anchor Pinning (AAP)
**Status:** Draft
**Created:** 2026-07-25

## 1. Context and Scope
As LLM context windows scale to 1M+ tokens (e.g., Gemini 1.5 Pro), a new failure mode has emerged: "Instruction Eviction." High-entropy noise generated by specialist subagents in deep meshes can "bury" core safety instructions and mission-root guardrails, leading to intent drift or safety bypasses. Standard context management often treats instructions and data with the same priority, allowing critical anchors to be evicted during garbage collection or summarization.

AAP provides a cognitive stability layer that ensures core behavioral anchors remain permanent and high-priority in the model's attention window by dynamically re-injecting them as "Attention Reinforcement" tokens.

## 2. Goals & Non-Goals
* **Goals:**
    * Guarantee the persistence of mission-root guardrails in large context windows.
    * Dynamically detect "Attention Decay" via reasoning entropy monitoring.
    * Implement "GC-Immune" pinning for specific context fragments.
    * Support hardware-attested anchoring of instructions to user intent.
* **Non-Goals:**
    * Modifying the underlying model's attention mechanism (handled at the prompt/API layer).
    * General-purpose context summarization (handled by QBS/ContextEngine).

## 3. Critical User Journey (CUJ)
* **User Persona:** Long-running Research Swarm Orchestrator
* **Primary Goal:** Ensure that a swarm of 20 agents stays within budget and safety constraints even after generating 800k tokens of research data.
* **The Happy Path (Tasks):**
    1. Orchestrator defines a "Mission Root" with specific safety constraints.
    2. AAP marks these constraints as "Permanent Anchors."
    3. As the swarm reasons, the context window fills with high-entropy research logs.
    4. AAP monitors the "Attention Density" and detects that anchor tokens are being pushed to low-priority regions.
    5. AAP triggers an "Attention Reinforcement" event, re-injecting the safety anchors into the most recent context segment.
    6. The subagents continue to honor the safety constraints despite the massive context size.

## 4. Design & Architecture
* **System Flow:**
    `[Reasoning Trace] -> [Entropy Monitor] -> [AAP Controller] -> [Attention Reinforcer] -> [Model Input]`
* **APIs / Interfaces:**
    * `aap.RegisterAnchor(fragment_id, priority_score)`: Pins a fragment.
    * `aap.InjectReinforcement(context_window) -> ReinforcedWindow`: Re-prioritizes anchors.
* **Data Storage/State:**
    * Stores an "Anchor Registry" bound to the current hardware-attested session.

## 5. Alternatives Considered
* **Static System Prompts (Rejected):** Ineffective in very large windows where the model loses focus on the beginning of the prompt (Lost-in-the-Middle).
* **Aggressive Summarization (Rejected):** Can lead to "Mission-Root Erasure" where critical nuances are lost in the summary.

## 6. Cross-Cutting Concerns
* **Security (Zero Trust):** Anchors are cryptographically linked to the user's initial hardware-attested intent.
* **Observability:** Visualized in the "Attention Map" dashboard showing anchor strength over time.
