# Design Doc: Non-Linear Policy Validator (NLPV)
**Status:** Draft
**Created:** 2026-04-14

## 1. Context and Scope
Recent findings (Adversa AI, April 2026) revealed a "Token-Saving" bypass in mainstream AI coding agents where security checks are truncated for complex command pipelines (e.g., >50 subcommands). This structural conflict between inference cost and security creates a "Shadow Path" for RCE. MCP Any, as a universal gateway, must provide a native, token-independent validation layer that performs exhaustive semantic analysis regardless of command complexity.

## 2. Goals & Non-Goals
* **Goals:**
    * Provide a native (Go-based) validation engine for command-line tools.
    * Perform exhaustive, non-truncated scanning of all subcommands in a pipeline.
    * Decouple security enforcement from LLM token costs.
    * Implement a "Complete-Validation-or-Deny" gate for all tool calls.
* **Non-Goals:**
    * Replacing existing LLM-based intent validation (NLPV works as a deterministic fallback).
    * Implementing a full shell emulator.

## 3. Critical User Journey (CUJ)
* **User Persona:** Enterprise Security Architect
* **Primary Goal:** Ensure "never run curl" policy is enforced even in complex 100+ command build scripts generated by an agent.
* **The Happy Path (Tasks):**
    1. Architect defines a `deny: ["curl"]` policy in MCP Any.
    2. A malicious repository instructs an agent to run a 60-command pipeline where the 51st command is a `curl` exfiltration.
    3. The tool call reaches MCP Any's NLPV middleware.
    4. NLPV exhaustively parses the entire string, identifying the `curl` statement at position 51.
    5. The call is blocked *before* execution, even if the LLM provider's internal checks were bypassed or truncated.
    6. A "Complexity Threshold Bypass Blocked" alert is logged.

## 4. Design & Architecture
* **System Flow:**
    * Intercepts tool calls at the middleware layer.
    * Tokenizes shell command strings into discrete subcommands.
    * Iterates through *all* subcommands against the current security profile.
    * Uses a deterministic finite automaton (DFA) for fast, exhaustive matching.
* **APIs / Interfaces:**
    * `ValidateCommandPipeline(cmd string, profile SecurityProfile) bool`
    * `RegisterComplexityGate(threshold int, action PolicyAction)`
* **Data Storage/State:** Uses existing MCP Any policy definitions (Rego/CEL).

## 5. Alternatives Considered
* **LLM-Based Exhaustive Scanning**: Rejected due to prohibitive token costs and potential for "Reasoning Fatigue" leading to false negatives.
* **Native Shell Sandboxing (gVisor)**: Complementary, but doesn't prevent "Logical Bypasses" where an agent uses legitimate tools in unauthorized ways.

## 6. Cross-Cutting Concerns
* **Security (Zero Trust):** Eliminates the "Complexity as a Cloak" attack vector.
* **Observability:** Provides detailed "Policy Intersection" reports showing exactly which part of a complex command triggered a block.
