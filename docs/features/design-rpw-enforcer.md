# Design Doc: Reasoning-Path Watermark (RPW) Enforcer
**Status:** Draft
**Created:** 2026-07-25

## 1. Context and Scope
With the EU AI Act enforcement beginning in August 2026, organizations must provide non-repudiable proof that autonomous agent actions are aligned with their intended mission roots. Current "Reasoning Monologues" are text-based and can be spoofed or pruned by malicious subagents.

The RPW Enforcer embeds cryptographic watermarks into the "Chain-of-Thought" (CoT) at the transport layer. It ensures that every reasoning fragment generated by an agent is traceable back to the user's hardware-attested intent.

## 2. Goals & Non-Goals
* **Goals:**
    * Embed TPM-signed watermarks into every CoT reasoning fragment.
    * Bind reasoning fragments to a specific "Compliance Manifest."
    * Ensure watermarks survive context window summarization and garbage collection.
    * Provide a verifiable audit trail for regulatory compliance.
* **Non-Goals:**
    * Modifying the LLM's internal weights (RPW is a middleware-layer injection).
    * Preventing hallucinations (RPW only ensures *traceability* of hallucinations).

## 3. Critical User Journey (CUJ)
* **User Persona:** Compliance Auditor
* **Primary Goal:** Verify that a financial transaction performed by a swarm was authorized by the Mission Root manifest.
* **The Happy Path (Tasks):**
    1. Auditor requests the "Provenance Trace" for Transaction ID #8892.
    2. MCP Any retrieves the RPW-encoded CoT fragments from the Regulatory Vault.
    3. The RPW Validator verifies the cryptographic hash-chain between the Tool Call and the Parent Intent.
    4. The Auditor confirms that the embedded "Compliance Signature" matches the TPM key of the authorizing human.
    5. Non-compliance alerts are suppressed.

## 4. Design & Architecture
* **System Flow:**
    ```mermaid
    sequenceDiagram
        Agent->>RPW Enforcer: CoT Fragment (Draft)
        RPW Enforcer->>TPM: Sign Fragment Hash + Mission ID
        TPM-->>RPW Enforcer: Cryptographic Watermark
        RPW Enforcer->>Agent: CoT Fragment + Watermark
        Agent->>Blackboard: Commit State
    ```
* **APIs / Interfaces:**
    * `x-mcp-rpw-signature`: Header injected into all inter-agent transport (BSH/Pipes).
    * `/v1/compliance/verify`: Endpoint for auditors to validate a chain of watermarked fragments.
* **Data Storage/State:**
    * Watermarks are stored in a write-once, audit-only SQLite sidecar (Regulatory Vault).

## 5. Alternatives Considered
* **Textual Watermarking:** Rejected because LLM summarizers frequently strip "Invisible" text tags.
* **Post-hoc Logging:** Rejected because it doesn't provide real-time interdiction of non-compliant reasoning branches.

## 6. Cross-Cutting Concerns
* **Security (Zero Trust):** RPW keys are rotation-mandatory and hardware-bound. Any attempt to strip a watermark triggers an immediate "Mission Failure" signal.
* **Observability:** RPW "Watermark Density" is visualized in the Reasoning Lineage Inspector.
