# Design Doc: Reasoning Provenance Validator
**Status:** Draft
**Created:** 2026-06-29

## 1. Context and Scope
With the introduction of the `x-gemini-provenance` standard, AI agents can now provide cryptographically signed "Chain of Thought" steps. This is a critical evolution in agent security, as it allows infrastructure to verify that an agent's reasoning was not tampered with or influenced by un-attested state fragments during generation.

The Reasoning Provenance Validator acts as the authoritative verification engine for these signed reasoning traces. It ensures that every step in an agent's logic is hardware-bound and consistent with the mission-root intent, neutralizing "Hallucination Hijacking" where an agent is coerced into malicious reasoning via indirect injection.

## 2. Goals & Non-Goals
* **Goals:**
    * Validate `x-gemini-provenance` headers against hardware-attested public keys.
    * Verify the semantic continuity between signed reasoning fragments.
    * Provide a "Reasoning Integrity Signal" to the Policy Engine for tool-call authorization.
* **Non-Goals:**
    * Re-running the LLM inference (this is a cryptographic and semantic validation only).
    * Restricting reasoning for low-risk, non-delegated tasks.

## 3. Critical User Journey (CUJ)
* **User Persona:** Enterprise Security Auditor
* **Primary Goal:** Verify that a complex "Cloud Deployment" plan generated by a swarm of 5 agents was actually reasoned through step-by-step without being hijacked by a malicious repository hook.
* **The Happy Path (Tasks):**
    1. The lead agent generates a deployment plan, signing every reasoning step with its TPM-bound key.
    2. The plan is submitted to MCP Any for tool execution.
    3. The Reasoning Provenance Validator intercepts the request and extracts the `x-gemini-provenance` traces.
    4. The Validator verifies the hardware signatures and checks the hash-chain of the reasoning steps.
    5. The Validator issues a "Trusted Reasoning" token, allowing the `run_terraform` tool to proceed.

## 4. Design & Architecture
* **System Flow:**
    ```mermaid
    graph TD
        Agent[Agent / LLM] -->|Signed Reasoning| RPV[Reasoning Provenance Validator]
        RPV -->|Verify Signatures| TPM[Hardware TPM/KMS]
        RPV -->|Validate Chain| SCM[Semantic Continuity Monitor]
        RPV -->|Integrity Score| Policy[Policy Engine]
        Policy -->|Allow/Deny| Tool[Tool Execution]
    ```
* **APIs / Interfaces:**
    * `VerifyProvenance(trace []ReasoningStep) (bool, error)`: Core internal API for validating hash-chained reasoning.
    * `x-gemini-provenance` header support in all JSON-RPC methods.
* **Data Storage/State:**
    * Short-lived cache of verified reasoning hashes to prevent replay attacks.

## 5. Alternatives Considered
* **Full Monologue Logging:** Rejected due to privacy concerns and token bloat. Provenance headers provide a more compact and secure verification signal.
* **Reactive Verification (Human Review):** Rejected as it does not scale with "Machine-Speed Swarms."

## 6. Cross-Cutting Concerns
* **Security (Zero Trust):** Reasoning provenance ensures that the "intent" of the user is preserved even through multiple delegation hops.
* **Observability:** The "Reasoning Lineage Inspector" UI component will allow users to visualize the verified chain of thought.
