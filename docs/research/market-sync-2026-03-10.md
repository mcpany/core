# Market Sync: 2026-03-10

## Ecosystem Updates

### OpenClaw: Swarm Protocol v2
OpenClaw has moved towards a decentralized discovery mechanism where subagents can "advertise" their own local tools to the swarm. This bypasses central registries and creates a "Shadow MCP" problem where tools are used without central oversight.

### Claude Code: Ephemeral Tooling
Claude Code now supports "runtime-defined tools" that are generated by the LLM and executed via a local shim. These tools don't have static schemas or persistent identifiers, making traditional ACLs and Policy Engines (like Rego) difficult to apply.

### Agent Swarms: Recursive Prompt Injection
A new attack vector has been identified where a malicious subagent can return a crafted response that, when ingested by the parent agent, acts as a "context-level instruction" to bypass the parent's safety filters. This is being called "Recursive Context Poisoning."

## Autonomous Agent Pain Points
- **Discovery Overload**: Swarms are struggling with "Tool Fatigue" as the number of advertised tools grows exponentially.
- **Policy Latency**: Applying complex Rego policies to thousands of ephemeral tool calls is introducing significant latency in agent loops.
- **Identity Fragmentation**: No standard way to verify if a tool call "from Agent B" was actually authorized by "Agent A" (the orchestrator).

## Security Vulnerabilities
- **Blackboard Side-Channels**: Multi-agent blackboards (Shared KV) are vulnerable to timing attacks where one agent can infer the presence of data in another agent's isolated scope.
- **Ephemeral Tool Escapes**: LLM-generated tools often lack basic input sanitization, leading to local RCE if the parent agent doesn't strictly sandbox the execution shim.
